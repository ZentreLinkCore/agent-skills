Applies to any Expo app in a project. Read [frontend.md](./frontend.md) for the shared frontend rules; this file adds what is specific to mobile. **Web and mobile are separate scopes**: a mobile task does not read web code, and the reverse ([context-budget.md §4](../context-budget.md#4-scope)).

## 2. Rules

- **Expo APIs change every SDK.** Read the app's `expo` major version in its `package.json` and use the docs for that version (`https://docs.expo.dev/versions/v<major>.0.0/`); never write Expo, EAS, or React Native APIs from memory.
- **Install packages with `npx expo install <package>`**, never `npm install`, so versions match the SDK. Dev-only test tooling follows [testing.md](./testing.md#setting-up-a-missing-frontend-runner-one-time-done-by-the-skill).
- **Follow the app's own layout and HTTP client** (find the client under `src/app/axios/` or `src/api/`); verify how it unwraps responses before adding `.data`.
- **Secure storage for secrets**: tokens and credentials go in the platform's secure store (`expo-secure-store` where the app has it), never plain async storage.
- **Native vs. OTA.** A change to native config (`app.json` plugins, permissions, native modules, the runtime version) needs a new native build; an OTA update does not reach installs built on another runtime. Say which one the change needs. (Expo)'s `app.json` uses `runtimeVersion.policy: "appVersion"`, so every version bump is a new runtime.
- **Generated folders are not source**: never edit `android/`, `ios/` (regenerated by `expo prebuild`), `dist/`, or `node_modules/`.
- **Platform differences**: check both iOS and Android behavior for permissions, keyboard, safe areas, and back navigation; a web-only check is not a mobile check.
- **Checks**: `npm test` where configured, plus `npx tsc --noEmit` and `npx expo lint`.
- **Version bumps** for a versioned app follow [versioning.md](./versioning.md) and the project's `.agents/config/<project>.yml`.
