# .agents

AI agent rules and workflow skills for Laravel projects with a Vue or React frontend. Each project's own facts live in its profile; everything else is project-neutral.

- [AGENTS.md](./AGENTS.md) - entry point: full list of rules and the `/webkit-*` skill workflow.
- [rules/project-profile.md](./rules/project-profile.md) - **start here**: the verified, concrete architecture of each project (backend patterns, route prefixes, frontend layout), keyed by its `<source-path>`. The other rules are generic; this one is the facts.
- [rules/](./rules/) - coding, architecture, security, and domain rules the agent must follow.
- [skills/](./skills/) - `/webkit-specify`, `/webkit-implement`, `/webkit-verify`, `/webkit-code-review`, `/webkit-design-review`, `/webkit-investigate`, `/webkit-fix`, `/webkit-refactor`, `/webkit-document`, `/webkit-migrate` — the concrete workflow built on top of the rules.
- [template/](./template/) - the formats every skill writes in, so each document has one fixed structure. Saved documents: [feature-specification.md](./template/feature-specification.md) (`/webkit-specify` → `spec.md`), [investigation-report.md](./template/investigation-report.md) (`/webkit-investigate` → `investigation.md`), [refactor-report.md](./template/refactor-report.md) (`/webkit-refactor` → `refactor.md`), [verification-report.md](./template/verification-report.md) (`/webkit-verify` → `verify.md`), [code-review-report.md](./template/code-review-report.md) (`/webkit-code-review` → `code-review.md`), [design-review-report.md](./template/design-review-report.md) (`/webkit-design-review` → `design-review.md`), [feature-guide.md](./template/feature-guide.md) (`/webkit-document` → `.agents/docs/<feature>.md`), [migration-contract.md](./template/migration-contract.md) (`/webkit-migrate` → `.agents/migrations/…`). Chat summaries: [implementation-summary.md](./template/implementation-summary.md) (`/webkit-implement`), [fix-summary.md](./template/fix-summary.md) (`/webkit-fix`), [migration-summary.md](./template/migration-summary.md) (`/webkit-migrate`).
- [specs/](./specs/) - one **ticket folder** per piece of work, inside its project (`specs/<project>/T00001/` holding `spec.md` (`specs.md` on older tickets), `investigation.md`, `refactor.md`, `verify.md`, `code-review.md`, `design-review.md` — whichever its work produced), implemented on a branch named `T00001`. Convention: [rules/ticket-numbering.md](./rules/ticket-numbering.md).
- [docs/](./docs/) - human-readable reference docs on how existing features actually work (e.g. [docs/duty-roster.md](./docs/duty-roster.md)) — distinct from `specs/` (per-ticket working documents).
- [reports/](./reports/) - the pre-ticket archive of investigation and review reports, plus the fallback for work that has no ticket. New ticketed work writes into its ticket folder instead.
