## 4.12 Realtime Provider Strategy

The application shall separate the internal event model from the specific realtime provider.

For example:

```text
Application Event
      │
      ▼
MessageSent
      │
      ▼
Realtime Broadcasting Layer
      │
      ├───────────────┐
      ▼               ▼
   Pusher           Reverb
  Production      Development
```

The client should consume application-level events rather than being tightly coupled to provider-specific business logic.

The initial environment strategy is:

| Environment       | Primary Realtime | Fallback                         |
| ----------------- | ---------------- | -------------------------------- |
| Local Development | Pusher           | Reverb                           |
| Test/QA           | Pusher           | Configurable                     |
| Staging           | Pusher           | Configurable                     |
| Production        | Pusher           | Based on deployment architecture |

The fallback mechanism shall avoid broadcasting the same event through both providers simultaneously unless there is an explicit architectural reason to do so.
