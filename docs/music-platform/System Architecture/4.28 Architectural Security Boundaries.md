## 4.28 Architectural Security Boundaries

The architecture shall define clear security boundaries.

```text
┌─────────────────────────────────────────┐
│              Public Client              │
│                                         │
│ React / Mobile / Desktop                │
└───────────────────┬─────────────────────┘
                    │ HTTPS
                    ▼
┌─────────────────────────────────────────┐
│             Application API             │
│                                         │
│ Auth / Authorization / Validation       │
└───────────────────┬─────────────────────┘
                    │
          ┌─────────┼─────────┐
          ▼         ▼         ▼
      Database    Redis   External APIs
```

Sensitive infrastructure resources shall not be directly exposed to clients.

For example:

```text
Client
  ✗ Direct PostgreSQL access
  ✗ Direct Redis access
  ✗ Database credentials
  ✗ Pusher secret
  ✗ Music provider private credentials

Client
  ✓ Public API configuration
  ✓ Authorized API requests
  ✓ Realtime client credentials where appropriate
```
