## 4.11 Realtime Communication Architecture

The system shall use a realtime communication provider for events that need to be delivered to connected clients.

The initial production-oriented provider shall be **Pusher**.

Laravel Reverb may be used as a development fallback or alternative where the environment supports persistent WebSocket processes.

The architecture shall keep realtime functionality provider-independent.

```text
Laravel Application
        │
        │ Broadcast Event
        ▼
┌───────────────────────┐
│   Realtime Provider   │
│                       │
│       Pusher          │
└───────────┬───────────┘
            │
       WebSocket
            │
     ┌──────┼──────┐
     ▼      ▼      ▼
   User A User B User C
```

Examples of realtime events include:

```text
message.sent
message.updated
message.deleted
message.reaction_added
message.typing
message.read

user.online
user.offline

community.member_joined
community.member_left

jam.joined
jam.left
jam.play
jam.pause
jam.seek
jam.track_changed
jam.state_updated
jam.ended
```
