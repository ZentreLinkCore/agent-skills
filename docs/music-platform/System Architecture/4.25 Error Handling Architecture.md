## 4.25 Error Handling Architecture

Errors shall be handled at appropriate layers.

```text
Client
  │
  ▼
API
  │
  ├── Validation Error
  ├── Authentication Error
  ├── Authorization Error
  ├── Business Rule Error
  ├── Not Found
  └── Server / Dependency Error
```

The API shall return standardized responses.

A conceptual error response may be:

```json
{
  "success": false,
  "message": "You are not authorized to access this conversation.",
  "error_code": "CONVERSATION_ACCESS_DENIED",
  "request_id": "req_abc123"
}
```

The system shall avoid exposing internal stack traces, database credentials, provider secrets, or sensitive implementation details to clients.
