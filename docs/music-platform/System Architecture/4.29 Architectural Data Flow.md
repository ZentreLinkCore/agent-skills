## 4.29 Architectural Data Flow

A typical message transaction shall follow:

```text
1. User enters message
          │
          ▼
2. React client sends API request
          │
          ▼
3. Laravel authenticates user
          │
          ▼
4. Laravel checks authorization
          │
          ▼
5. Laravel validates request
          │
          ▼
6. Message is persisted
          │
          ▼
7. Transaction is committed
          │
          ▼
8. MessageSent event is dispatched
          │
          ▼
9. Pusher distributes event
          │
          ▼
10. Connected clients update UI
```

A Jam playback operation follows a similar pattern:

```text
Host presses PLAY
        │
        ▼
POST /jams/{jam}/play
        │
        ▼
Laravel validates Jam permission
        │
        ▼
Jam state updated
        │
        ▼
Playback event generated
        │
        ▼
Pusher
        │
        ▼
Participants receive event
        │
        ▼
Clients synchronize local playback
```
