## 4.10 Redis Architecture

Redis shall be used for high-speed temporary or asynchronous workloads.

Potential Redis responsibilities include:

* Application caching
* Queue management
* Rate limiting
* Temporary state
* Job coordination
* Presence-related temporary information where appropriate

Redis shall not automatically be treated as the permanent source of truth for business-critical records.

For example:

```text
Message
   │
   ▼
PostgreSQL → Permanent Record

Typing Indicator
   │
   ▼
Realtime / Temporary State

Cache
   │
   ▼
Temporary Representation
```

If Redis data is lost, the system should be able to reconstruct important persistent information from PostgreSQL.
